# miniTrek · 轻量家庭旅行规划平台 — 需求文档（PRD）

> 版本：v0.3　日期：2026-09-02　状态：MVP 开发完成（含导入导出）
> 关联文档：`docs/TECHNICAL.md`（技术方案）

---

## 1. 项目概述

### 1.1 一句话定位
**家庭出行决策助手**：帮助用户把"想去哪、怎么走、带谁去、要花多少钱、万一变了怎么办"从零散想法整理成一份可执行、可分享、可记账的旅行行程。

### 1.2 背景与动机
- 参考产品：Trek 等 AI 旅行规划平台（提供行程时间线 + 地图 + 地点面板的一体化规划体验）。
- 差异化：面向**国内家庭用户**（尤其带老人/儿童），聚焦"亲子/家庭节奏"，不重复做预订交易闭环。
- 平台本身**不内置 AI 规划能力**，而是通过 **MCP 接口** 让用户自己的 AI 客户端连接来完成规划，平台专注"展示 + 手动编辑 + 数据管理"。

### 1.3 目标用户
- 核心用户：有家庭出行需求的个人规划者（夫妻一方负责全流程规划）。
- 家庭成员：老人、成人、儿童、婴儿，需在行程中体现差异化需求（节奏、票务规则、体力）。

## 2. 需求定稿（决策表）

| 决策项 | 结论 |
|---|---|
| 产品形态 | **Web 版**，桌面端优先（本项目暂不考虑手机端适配） |
| 使用模式 | **单人规划** + 可生成**只读分享链接**给家人查看 |
| 规划方式 | 三通道：① AI 通过 MCP 规划 ② 手动规划 ③ AI 生成后手动微调 |
| 平台职责 | 行程**展示 + 手动编辑 + 数据存储**，不含任何预订/交易 |
| 交通 | 平台**查询**车次/时刻/票价（12306 数据），用户自行在 12306 预订 |
| AI 接入 | 提供 **MCP Server**，暴露行程/车次/天气/POI/清单工具，**API Token** 认证 |
| 部署 | 飞牛 NAS（Docker，单容器），数据库 **SQLite** 挂存储卷 |
| 二级标签（详情页） | MVP 仅做：**计划 / 交通 / 费用**（参考图原有 8 个，其余后续迭代） |
| 首页入口 | **新建行程**（手动）+ **AI 规划**（引导连接 MCP）两个入口都要 |

## 3. 用户与使用流程

### 3.1 角色
| 角色 | 说明 |
|---|---|
| 规划者（唯一操作者） | 创建、编辑、管理所有行程 |
| 家人（只读） | 通过分享链接查看行程，不登录、不可编辑 |

### 3.2 主流程
```
打开首页（行程项目列表）
  → 新建行程（填写标题/出发地/目的地/日期/成员） 或  通过 AI/MCP 规划生成
  → 进入行程详情页：查看每日时间线 / 地图点位 / 编辑节点 / 查交通 / 记账
  → 微调行程（拖拽排序、增删节点、标记"待预订/已预订"）
  → 生成只读分享链接发给家人
```

### 3.3 典型用户故事
- **US-1**：作为家长，我创建"五一郑州→大理 5 天"行程并录入 2 大人 1 儿童（5 岁），AI 生成的行程会自动放慢节奏、预留午休。
- **US-2**：作为规划者，我查看行程详情页，左栏看到每天安排、中间地图看到点位、右栏可搜索地点拖入行程。
- **US-3**：作为规划者，我在"交通"标签页查郑州东→大理的车次、时刻、票价，选定后挂到某一天的行程节点，并标记"待预订"。
- **US-4**：作为规划者，我把行程链接发到家庭群，家人无需登录即可只读查看。
- **US-5**：作为规划者，我随时能看本次旅行总费用及各天费用明细。

## 4. 功能需求

### 4.1 首页（行程项目列表）
| 编号 | 需求 | 说明 |
|---|---|---|
| H-01 | 行程项目列表 | 以卡片/列表展示所有旅行项目 |
| H-02 | 项目信息 | 标题、出发地→目的地、出行日期、天数、状态、总费用 |
| H-03 | 新建行程 | 手动创建入口，弹出表单（标题/出发地/目的地/起止日期/成员） |
| H-04 | AI 规划入口 | 快捷入口，弹窗为「MCP 接入配置」3 步引导：① 生成/复制 API Token ② 填写平台可访问地址（DDNS/内网 IP）③ 按客户端（通用/Claude、Cursor、豆包）一键导出可复制的 MCP 配置 JSON 或下载 `.json`，并说明 Token 生成方法 |
| H-05 | 进入详情 | 点击项目卡片进入行程详情页 |

### 4.2 行程详情页（核心页面，参考 Trek 三栏布局）
**顶部栏**：返回、平台名、行程标题、编辑、分享、**导出、导入**、当前用户。
**二级标签**：计划 / 交通 / 费用（MVP）。

#### 计划标签（三栏）
| 栏 | 内容 | 关键点 |
|---|---|---|
| 左栏·时间线 | 按天分组（第N天 + 日期 + **自动天气**），节点带类型徽标（住宿/交通/地点/计划/餐饮）平铺展示，每天含费用小计 | 支持增删节点；节点**拖拽排序（天内跨类型 + 跨天随意调整）**；住宿/车次带"待预订"状态标记；底部汇总总费用；顶部「编辑」可改行程标题/出发地/目的地/起止日期 |
| 中栏·地图 | 高德地图，标注行程点位 | 与左栏选中日期联动（浮层显示当前日期）；点击点位弹详情 |
| 右栏·地点面板 | POI 搜索、候选列表（名称+地址+类型）、"未规划/已规划"计数 | 点击候选一键加入当前选中天（带坐标）；对应手动规划通道 |

**天气**：进入行程自动按目的地城市 + 各天日期查询（Open-Meteo 免费源），已手工填写的保留；每日天气徽章可点击进入弹窗"自动查询 / 手工编辑"；超出预报范围（约 16 天）给出提示。

#### 交通标签
| 编号 | 需求 | 说明 |
|---|---|---|
| T-01 | 车次查询 | 输入出发地/到达地/日期，查询车次、时刻、历时、席别票价 |
| T-02 | 车次入行程 | 选中某车次，挂到指定日期的交通节点，标记"待预订" |
| T-03 | 免责提示 | 展示"余票/票价以 12306 为准"提示，不引导线上预订 |

#### 费用标签
| 编号 | 需求 | 说明 |
|---|---|---|
| C-01 | 费用明细 | 按天/按类别（交通/住宿/门票/餐饮）汇总 |
| C-02 | 总费用 | 各节点费用自动汇总，实时刷新 |
| C-03 | 节点计费 | 交通/住宿/门票节点可填费用金额，景点等可留空 |

### 4.3 手动规划
- 支持直接在时间线新增"住宿/景点/交通/餐饮/备注"类型节点。
- 支持从右栏地点面板搜索并拖入行程。
- 支持节点排序、删除、编辑（名称/地址/时间/费用/备注/预订状态）。

### 4.4 AI 规划（MCP）
- 平台提供 MCP Server，用户在自己的 AI 客户端（支持 MCP 的豆包/Claude/Cursor 等）中配置 Server 地址 + API Token。
- AI 通过工具调用创建行程、建天、加节点、查车次、查天气、查 POI、写清单，数据实时写入平台并在 Web 端展示。
- 详见技术方案第 5 章工具清单。

### 4.5 分享
| 编号 | 需求 | 说明 |
|---|---|---|
| S-01 | 生成分享链接 | 一键生成带随机 token 的只读链接 |
| S-02 | 只读访问 | 链接访问者只能查看，不可编辑 |
| S-03 | 链接管理 | 可撤销/重新生成链接 |

### 4.6 出行清单
- 每个行程可维护一份物品清单（如婴儿用品、赶海装备、证件）。
- AI 可通过 MCP 写入清单项；Web 端可勾选完成。

### 4.7 家庭画像（简版）
- 创建行程时录入成员：角色（成人/儿童/婴儿/老人）、年龄/出生年、备注（如"需午休""推车"）。
- 供 AI 规划时参考（提示词上下文），Web 端只读展示。

### 4.8 导入 / 导出（Markdown）
| 编号 | 需求 | 说明 |
|---|---|---|
| IE-01 | 导出行程 | 详情页「导出」将当前行程下载为标准 `.md`（标题/出发/目的地/日期/每日天气/分类节点/地址/时间/备注/费用/预订状态） |
| IE-02 | 导入行程 | 详情页「导入」弹窗支持**粘贴 md / 上传 .md / 一键填入格式模板**，解析后展示可导入摘要（标题/天数/节点数） |
| IE-03 | 导入行为 | 确认后**新建**一个行程（不覆盖原行程）并自动跳转 |
| IE-04 | 格式模板 | 弹窗内置标准格式模板，方便用户手写 md 后导入；格式契约见技术方案 4.1 节 |
| IE-05 | 往返无损 | 导出文件可直接再导入，字段无丢失（已自动化测试 + 浏览器实测） |

## 6. 非功能需求

| 项 | 要求 |
|---|---|
| 部署形态 | 飞牛 NAS，Docker 单容器，数据落本地卷 |
| 性能 | 单用户场景，页面秒开；车次/地图查询异步加载 |
| 数据安全 | 本地私有部署；MCP 接口需 Token 鉴权；分享链接随机 token |
| 可备份 | SQLite 单文件，支持直接复制备份 |
| 可扩展 | 数据层用 ORM 抽象，预留迁移 Postgres 的能力 |
| 兼容 | 桌面浏览器（Chrome/Edge），本项目不做移动端适配 |
